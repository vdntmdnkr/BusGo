[SLIDE 5: COMPREHENSIVE CLIENT-SIDE VALIDATION MATRIX]
Slide Title:
Client-Side Validation Modules

1. Passenger & Auth Validation:
• Full Name: String check (3–40 characters, letters and spaces only).
• Email Address: Standard RFC 5322 regex check (name@domain.extension).
• Age: Integer boundary check (between 5 and 100 years).
• Terms & Conditions: Mandatory checkbox boolean validation.

2. International Phone Validation:
• Supports 10+ country dialing codes (+91, +1, +44, +971, +65, etc.).
• Enforces country-specific length and numeric regex patterns in real time.

3. Route & Schedule Validation:
• Prevents identical Source and Destination cities.
• Disallows past journey dates by comparing against current UTC/Local date.

4. Financial & Payment Validation:
• Card Number: 16-digit format with automatic 4-digit space masking.
• Expiry Date: MM/YY format with month (01–12) and future year validation.
• CVV: 3 to 4 numeric digits only.
• UPI VPA: Regular expression check (username@bank).

[SLIDE 6: CORE FEATURE 1 — INTERNATIONAL PHONE REGEX VALIDATION]
Slide Title:
Feature 1: International Phone Validation Engine

How It Works:
1. User selects country flag and dialing code from dropdown (+91 India, +1 USA, +44 UK, +971 UAE).
2. Dynamic input masking strips unwanted symbols (brackets, dashes, spaces).
3. Executes country-specific Regular Expression:
   • India (+91): /^[6-9]\d{9}$/ (10 digits starting with 6, 7, 8, or 9)
   • USA/Canada (+1): /^\d{10}$/ (Standard 10 numeric digits)
   • UK (+44): /^[1-9]\d{9}$/ (10 digits starting with non-zero)
   • UAE (+971): /^[5]\d{8}$/ (9 digits starting with 5)
4. Displays instant helper hint (e.g., "Format requirement: 10 digits starting with 6-9").
5. Blocks form submission with visual red error state if invalid.
